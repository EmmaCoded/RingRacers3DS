# Ring Racers on the Nintendo 3DS

This branch ports [Dr. Robotnik's Ring Racers](https://github.com/KartKrewDev/RingRacers) (base commit
`49beb6b`, v2.4) to the **Old Nintendo 3DS** using devkitPro, libctru and citro3d. It targets the
weakest member of the family: a 268 MHz dual-core ARM11, 64 MB of application memory, 6 MB of VRAM and a
400x240 top screen. The same tree also builds the PC edition ("Ring Racers E"); the 3DS code lives behind
`__3DS__` / `RR3DS` and the shared "low-end" logic behind `RR_LOWEND_CODE`.

> This is an unofficial fan port. It is not affiliated with Kart Krew Dev. Game assets are **not**
> included: you convert your own copy of the game with the tools in `tools/` (see
> [BUILD_3DS.md](BUILD_3DS.md)).

| Racing | Working, **slow**: 765 Stadium ~16 fps on hardware, geometry-heavy maps such as Robotnik Coaster ~2.3 fps |
| Audio (effects, music, character voices) | Working (DSP-ADPCM) |
| Character mods (`.pk3` skins with sounds) | Working, up to 16 packs |
| Bottom screen (minimap, standings, touch buttons) | Working |

| HOME button | Known crash in the HOME Menu process, see [Known problems](#known-problems) |
| Final distribution as a single CIA (RomFS) | Not done |

"Hardware" numbers come from logs captured on a real Old 3DS; everything else was measured in the Azahar
emulator configured as an Old 3DS (64 MB, 100% CPU). On the one map where both were compared (Coaster) the
console and the emulator agreed within ~10%, but memory behaviour (fragmentation, file handles, SD speed) only
shows up on real hardware.

## Hardware limits that shaped the design

- **~16 open files at a time.** `.pk3` archives use an LRU of 4 handles; at most 3 texture parts are open.
- **64 MB total.** The heap is extremely fragmented after a few maps; see [Memory](#memory).
- **The CPU cannot write VRAM.** Uploads go through a linear staging ring and a GPU DMA copy
  (limited to ~20 copies / 768 KB per frame to avoid overflowing the GX command queue).
- **6 MB of VRAM**, about 0.5 MB free during a race.
- **Core 1 is capped** (30% on Old 3DS), so splitting the game logic across cores is not a win.
- Audio is hardware DSP-ADPCM only.

## What was changed

### Renderer (`src/hardware/r_citro3d`, `src/dummy/gpu_present_3ds.c`)
- New citro3d backend for the existing OpenGL-style HWR renderer, with its own texture manager
  (VRAM first, linear fallback, LRU eviction by *time*, deferred uploads when memory is short).
- Textures are pre-converted off-device to **ETC1 / ETC1A4**; common sprites are packed in a fixed atlas;
  textures are capped at 256 px.
- Static geometry cache (walls and planes keyed by sector/side signatures) and a per-zone fast path.
- Skybox rendered to a texture and reused for several frames (`sky_every`).
- Precomputed visibility (`.rrv`) and node pruning, generated by the PC "map preparer" (`.rr3` map packages).
- Screen wipes and menu blend layers composed on the GPU.
- Runtime budget governor (`budget`): measures real frame time and lowers the ring cap when over target.

### Memory (`src/z_zone.cpp`, `src/dummy/memtrack_3ds.cpp`)
- A **single arena** takes the free heap at boot; the zone allocator and every `malloc`/`new` >= 4 KB come from it.
- Fixed-size batching buffers in `.bss` (never grow); drawnode buffer reused every frame.
- Leak fixes: per-regeneration colormap allocations (`hw_cache.cpp`), ACS argument strings (an upstream leak,
  also present on PC), no deep copy of the map (it only served online play).
- Whole-WAD caching removed: assets are raw files on the SD card (ETC1 textures, DSP audio) and are streamed;
  per-map and per-character **preload lists** keep the SD idle during a race.
- A `fragment_heap=1` option in `rr_config.txt` reproduces console-like heap fragmentation inside the emulator.

### Game logic (shared "low-end" mode, `RR_LOWEND_CODE`)
- Idle rings sleep and are drawn from the clock; far-away rings/effects think less or are removed.
- Decorations that follow karts (charge aura, AMP, BLOCK, fog, smoke) move without `P_CheckPosition`.
- Weather particles follow the camera instead of covering the whole map.
- Fewer objects for explosions, mines, prison capsules and Shrink.
- At most 4 racers (you + 3 bots); bots refresh their distance to the finish line 1 tic in 4.
- Logic tic cap raised to 11 per frame so game time stays real on slow frames.

### Upstream bugs found along the way (fixed in this tree)
- `P_SetMobjState`: the recursion counter was never decremented, so every state change cleared a 28 KB buffer.
- `PositionFacesInfo` (HUD): an out-of-bounds write when no player had a position yet (bot races).
- ACS argument string leak (see above).

### Audio
- Effects (`sfx.rrp`) and music (`RRM2`/`RRMM`) are DSP-ADPCM; tracker music is rendered with libopenmpt.
- Music decoding and streaming run on core 1; the music resync that rewound the track every frame is disabled.

### Interface
- Bottom screen: minimap with racer faces, standings, lap counter and a touch button (reset / bail).
- Lazy character mounting: 63 vanilla characters are indexed at boot and mounted when selected.

### Tooling (`tools/`)
- Asset pipeline: `convert_*.py`, `prepare_3ds.py`, `make_patch3ds.py` (single `prepare_3ds.exe` for end users).
- `build3ds.sh` increments an automatic `1.0.N` version on every build.
- In-game diagnostics (`diag=1`) and the always-on frame accountant `[METER]`, see [PERFORMANCE.md](PERFORMANCE.md).

## Known problems

- **Heavy maps are slow.** Robotnik Coaster runs at ~2.3 fps (4 racers). The cost is split roughly
  60% game logic and 40% drawing, and no single hot spot remains; see [PERFORMANCE.md](PERFORMANCE.md).
- **Memory.** `RR_CityEscape` still does not fit; after a long session (many maps without restarting) linear
  memory shrinks ~0.5 MB per map and textures start to fail (grey/white quads, 1 fps). Restart the game
  every few maps. The leak has not been found.
- **White/grey quads on sprites.** Textures that do not fit the per-frame upload budget are deferred and
  drawn as a checkerboard until they are uploaded. Small textures were fixed (fewer deferrals); 64 KB ETC
  textures can still be deferred on the first frame of a race.
- **HOME button.** The crash dump belongs to the HOME Menu process, not the game; an audio-hold hook was added
  but is untested. Quit from the game menu instead.
- **Pico Park sky flicker** was fixed in the emulator (sky texture sampled outside its margin) but not
  confirmed on hardware.
- The final RomFS/CIA distribution is not done; assets are read from the SD card.

## What is missing

1. Simplify the geometry of heavy maps offline (fewer visible zones); this is the only lever left for drawing.
2. Per-map racer count (fewer bots on heavy maps); logic is the dominant cost there.
3. Upload several small textures in one DMA copy to remove the remaining deferred-texture quads.
4. Find the ~0.5 MB/map linear-memory leak.
5. A drawing thread on core 1 (estimated 4-8%).
6. CIA / RomFS packaging.
